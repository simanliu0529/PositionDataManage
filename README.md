# Gowalla 签到数据管理服务

四人课程项目起步版。原始 TSV 经清洗生成 CSV，离线导入器按用户 ID 分成两个分片。每个查询节点只打开自己的 SQLite 文件。浏览器通过同一个后端查询，后端按用户 ID 路由或并行访问两节点，统一排序并分页。

## 第一次运行

安装 Python 3.11 或以上版本。在终端进入本目录。Windows 如果没有 `python` 命令，可改用 `py -3`。全量数据尚未拿到时，先使用自带的六行构造样例。

```sh
python -m cleaning.clean sample/checkins.tsv data/clean.csv
python -m db.load data/clean.csv data
```

当前清洗器默认去重：应得到 6 行输入、5 行通过格式校验、剔除 1 行无效经纬度和 1 行重复，输出 4 行 CSV。入库阶段新增重复为 0，两个节点各 2 行、合计 4 行。导入器拒绝覆盖已有数据库；复跑请使用新的输出目录。

数据库表结构、全量 `clean.csv` 导入、校验报告及本地一键启动方式见 [数据库运行说明](db/README.md)。已有清洗 CSV 时直接入库，无需再次清洗。

保持三个终端打开，各执行一条命令，工作目录都是本目录。

```sh
python -m db.node data/node-0.sqlite 8100
python -m db.node data/node-1.sqlite 8101
python -m backend.app
```

打开 http://127.0.0.1:8000 。首页应该能看到两个节点的行数和 4 条签到。输入用户 ID 1 应返回 1 条记录并显示只查询一个节点。

已装 Docker 的小组也可在生成样例数据库后运行 `docker compose up`，三个服务会在不同容器中启动。此时直接访问同一个网页地址，无需再启动三个本地 Python 进程。两种启动方式选一种。

## 分工与协作

| 负责人 | 首个任务分支 | 工作范围 | 第一份交付 |
| --- | --- | --- | --- |
| 数据清洗 | `feature/cleaning` | `cleaning/`，确认原始字段、时间和校验规则 | 真实小样本、字段说明、清洗计数与剔除原因 |
| 数据库 | `feature/database` | `db/`、`compose.yaml`，负责两节点、分片、索引和导入 | 可复现的启动与导入步骤、各节点计数及跨节点查询结果 |
| 查询功能全栈 | `feature/checkin-query` | `frontend/` 和 `backend/`，负责从筛选条件到查询结果的完整功能 | 按用户或时空条件查询，结果可分页展示，并能处理空结果和错误 |
| 系统集成与验收 | `feature/integration` | 串起清洗、入库、启动与查询，维护启动说明及联调用例 | 在另一位组员的电脑上用同一批数据复跑，并核对数据库、API 和页面结果 |

`backend/` 和 `frontend/` 分别放 API 与页面代码。一个查询功能涉及两个目录时，可以放在同一个 PR。集成时发现问题，先记录样本、复现命令和预期结果，再交给对应模块负责人处理。字段、时间格式、分片规则或 API 发生变更时，请下游使用者一起 review，并同步更新约定与样例。

已克隆的项目可直接继续用。仓库所有者邀请其余组员加入，组员接受后从最新的 `main` 创建任务分支，本地验证后推送并提交 PR。已有分支和改动的同学可以继续用原分支。仓库当前公开，真实数据、生成的数据库和本机配置放在 `data/` 或组内共享位置，仓库使用构造样例。

## 数据与接口约定

原始 TSV 无表头，按 user_id、checkin_time、latitude、longitude、location_id 排列。清洗输出 CSV 有表头，列顺序相同。时间统一为整秒 UTC，ID 为文本，经纬度为十进制度。初版在入库阶段按五字段组合去重。导入日志满足“有效行数 = 去重行数 + 两节点入库数之和”。

- `GET /api/nodes` 返回 `{"nodes":[{"node":0,"count":2},{"node":1,"count":2}]}`，实际计数取决于数据。
- `GET /api/checkins` 支持 `start`、`end`、`west`、`east`、`south`、`north`、`user_id`、`limit`、`offset`。所有参数可省略。起始时间包含，结束时间排除，坐标边界包含，坐标框不跨 180° 经线。默认每页 50 条、最多 200 条，偏移上限 10000。
- 响应含 `items`、`queried_nodes`、`has_more`。记录包含五个数据字段以及分片内 ID `id` 和分片号 `node`。两者组合标识一条记录。时间倒序，同时间按分片内 ID 和节点号倒序。
- 节点内部接口为 `GET /count` 和 `GET /checkins`。各节点为全局分页返回本分片最靠前的 `offset + limit + 1` 条。后端合并后再取目标页。一个必需节点不可用时，查询返回错误。
