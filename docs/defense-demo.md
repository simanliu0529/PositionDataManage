# 课程答辩演示与技术追问

本文为约 9 分钟的内部开发验收流程。课程附件要求正式 PPT 不超过 5 分钟，正式汇报请用 [五分钟脚本](defense-five-minutes.md)。演示围绕“原始导入 → 自动清洗 → 时空组织 → 持久化 → 查询地图 → 数据导出 → 版本恢复”展开；不能把脚本本身当成功证据。

**当前模块边界：** 只改全栈，`cleaning/`、`db/` 保持已获取上游 `753ec0f` 原文。上一轮本地坐标修复已撤回，上游众数缺陷待清洗同学处理。下述空间预期已按原样上游重新计算：坐标报告数为 5、实际变化 3 且选错多数，Austin 矩形 5 条、1500 米半径 1 条。不能继续展示旧修复版“真实修复 2、矩形 10、半径 6”为当前正确结果。边界与交接见 [模块说明](module-boundaries.md)。

## 演示前准备

建议使用独立目录与端口，避免正式替换覆盖同学正在使用的真实活动批次：

```powershell
cd "E:\研一上\空间数据管理与质量控制（测绘工程案例）\gowalla-starter"
$env:CHECKIN_DATA = Join-Path (Get-Location).Path 'data/defense-demo'
.\.venv\Scripts\python.exe -m backend.manage init
.\.venv\Scripts\python.exe scripts/run_local.py --port 8032 --node-port 8230
```

打开 `http://127.0.0.1:8032/`。本专用环境的随机账号在 `data/defense-demo/local-accounts.json`，与原运行环境可能不同。保持终端运行，结束用 Ctrl+C。另一个终端如要管理该演示环境账号，须设置相同的 `CHECKIN_DATA`。

先上传并正式发布 `sample/checkins.tsv`，准备一个 4 条记录的基准批次 A，记录批次号。确认管理员和普通用户能分别登录，浏览器可加载 Austin 城市的真实 OSM 底图。网络不稳定时仅使用有合法授权的本地 XYZ 城市瓦片；坐标网格不能替代答辩要求的城市底图。浏览器下载目录准备为空，方便找到导出文件。

可公开的 `review-*` 样例全部为构造记录，无真实个人信息；位置为 WGS 84，城市区域选择 Austin。老师全量真实数据可以作为项目背景和另行测量对象，现场不必等待数百万行重新处理。

## 可选故障演示

节点中断会影响查询和发布，现场主动停进程容易打断主流程。优先展示专用环境已验收的失败任务与测试记录。若确实要现场演示，预先用三个独立终端启动网页 / 工作进程和两个节点：停止一个节点后，应看到必需节点不可用的 503，不能看到“返回了部分数据但仍称成功”；恢复节点后重试，活动批次应保持完整。

无效文件可在演示目录本地创建仅包含 `bad columns` 的 TXT 并试导入，应失败且保持活动版本。空文件、无有效行、不完整矩形和超过允许范围的半径也适合快速验证。不要在共享真实环境故障注入，不要用浏览器端到端脚本默认发布样例覆盖同学的活动数据。

## 值得讲清的技术亮点

- **真实清洗和可追溯。** 原样调用团队清洗，字段验证、UTC 规范化、去重、同刻冲突、隐含速度和舍入产生实际结果；原始 = 剔除 + 有效，有效 = 去重 + 两节点入库数。地点众数仍有已知缺陷，不能把原样执行与对账当作语义准确性证明。
- **时空语义明确。** 时间统一 UTC，区间左闭右开；矩形包含边界；半径先保守预筛再 Haversine 精筛，支持极点和日期变更线边界；GeoJSON 经度在前。
- **用户路由与持久化。** `sha256(user_id UTF-8).digest()[0] % 2` 决定分片；单用户查询只访问一个节点，其他查询聚合两个节点；SQLite 具有约束与查询索引。
- **发布与恢复。** 新文件写新快照，核验和节点探针通过后才切换活动指针；CAS 防止覆盖并发切换；历史快照保留，可审计回退。
- **前后端真实协作。** 持久任务不依赖页面存活，刷新可恢复进度；分页固定批次；地图、列表、目录和导出使用相同数据版本。

## 可能追问及回答边界

| 老师可能问 | 建议回答 |
| --- | --- |
| 与 Excel 查看 CSV 有何区别？ | 自动执行多阶段时空清洗、用户分片持久化、条件查询、城市地图、版本发布 / 回退和鉴权数据服务；用本次操作证据说明 |
| 清洗真的运行了吗？ | 展示原始异常、任务阶段、报告和真实前后样本；UTC / 去重可核对，plaza 暴露上游已知缺陷，不只展示预处理后结果 |
| 为什么发现众数错误却没直接改？ | 用户明确只允许修改全栈，不允许改清洗 / 数据库同学的目录；因此撤回本地算法修改，将可复现样例和期望交清洗负责人，全栈不偷偷替代规则 |
| 报告说修复 5，为什么只有 3 条变化？ | 当前上游对目标地点全部 5 条都计数，即使坐标未变化；还因初始坐标计数未刷新选错目标。页面和文档需标明这是上游报告口径，不是准确修复条数 |
| 众数修复会不会掩盖真实地点变化？ | 它假设一个 location_id 对应稳定地点，冲突取多数是规则选择；原始文件保留，规则有版本。未来需按来源置信度或时间分段处理 |
| 1000 km/h 为什么合理？ | 是可解释的异常筛选阈值，不是绝对真值；兼顾航空出行，仍可能误判。需要保留报告并根据任务调整，不能保证每条剔除都是真假标签 |
| 两个节点算分布式吗？ | 实现了分片、路由、聚合和节点故障边界；当前验证是本机双节点。跨主机自动分发、容灾复制和高可用尚未部署 |
| 为什么不用 PostGIS？ | 课程数据字段和查询范围下，现有 SQLite 加索引可完成验证；更复杂并发与空间分析再考虑迁移，避免为技术数量重写 |
| 用户和地点是关联表吗？ | 签到记录含用户和地点标识，按批次预计算用户 / 地点 / 月份目录；没有账号与签到用户混用，也未伪造地点名称元数据 |
| 地图为什么没有中国地图偏移？ | 存储和查询使用 WGS 84；OSM 城市底图采用 Web Mercator 显示，不需要 GCJ-02 偏移。未来换底图须按其坐标要求显式转换 |
| 聚合点是全量热点吗？ | 当前聚合是当前页的可读性处理，不能称为整批热力统计；已提供有数量与时间边界的单用户签到连线，真实轨迹还原与全量热点分析仍未实现 |
| 能处理任意大的文件吗？ | 不能这样承诺。上传有限制，清洗存在内存与排序成本，最新规则尚未全量性能复验；报告具体已测样本和环境 |
| 能导出全部几百万条吗？ | 网页已提供后台完整文件任务，真实 CSV 6430640 条完成并逐条下载校验；旧同步接口仍限 10000。完整导出受磁盘与执行时间约束，不能把单次结果当任意规模承诺 |
| 为什么没有注册与网页用户管理？ | 当前按管理员受控分配账号，CLI 支持新增、停用和重置；开放注册对课程核心数据管理没有必要，网页管理尚未实现 |
| 多个文件导入后会合并吗？ | 当前正式操作是整批替换，多版本保留，不是增量追加；同文件同规则同模式会幂等复用，避免重复导入 |
| 若清洗器升级，旧数据是否自动变化？ | 不会。新任务使用新版本，旧快照保留，重新导入后形成新批次，便于对照与回退 |
| 历史性能数字可代表现在吗？ | 不可以。旧规则全量结果仅作历史记录，本轮只引用实际执行过的当前规则测试 |

## 现场完成标准

必须实际看到：异常原始输入，真实任务与质量计数，新批次和双节点记录，用户 / 时间 / 空间查询，真实城市底图与点表联动，可打开的导出文件，管理员与普通用户边界，以及回退后计数变化。出现未实现或未验收项时，直接说明当前边界，不能以静态截图、装饰按钮或计划文档替代功能。
