# 查询功能第二轮本地验证说明

本轮在第一轮基础上完善城市底图、查询恢复和错误处理。仍使用构造样例与既有查询接口；未改动清洗、入库、节点或批次发布实现。所有修改留在本地 `feature/checkin-query`，不推送、不创建 PR。

## 启动与体验

启动命令与[第一轮](checkin-query-round1.md)一致。已有三个服务运行时无需重启，访问 http://127.0.0.1:8000/ 并按 Ctrl+F5 刷新。

1. 打开签到地图，查询用户 `1`。
2. 点击“加载城市底图”，可看到武汉城市底图与真实接口返回的样例点位。默认仍为无需网络的离线视图。
3. 拖动、缩放仅改变视野，提交条件后才查询。可在城市底图上框选范围，也可按当前视野查询。
4. 查询后刷新页面，恢复最近一次成功的条件、每页条数及页码，并重新请求数据。
5. 点击“切换离线视图”可主动关闭底图；网络失败或单次瓦片超过 10 秒时自动回退，保留查询条件和当前页结果。

## 实现边界

- 城市底图按当前视野加载 OpenStreetMap 标准瓦片。页面保留来源归属链接；使用浏览器默认缓存，不预下载、不批量离线缓存。交互停止 180 毫秒后更新可见瓦片，已有瓦片复用。
- 在线底图和点位统一采用 Web Mercator 显示投影；接口和数据库仍使用原有 WGS 84 经纬度，不改变筛选坐标。极地坐标超过 Web Mercator 可表示范围时保留离线视图。
- 查询记忆仅在当前标签页的 `sessionStorage` 中保存成功的筛选、每页条数和偏移，不保存结果明细、不保存未提交或失败的条件。刷新后重新查询，旧接口没有批次固定语义，数据重新导入后结果可能变化。
- 保存内容损坏或浏览器不允许存储时，回到默认查询或提示存储不可用；不影响继续查询。重置后成功的默认查询覆盖此前记忆。
- 查询 API 调用集中在 `queryAPI` 接入层。新增 12 秒超时、网络失败、非 JSON 响应和 `message/error/request_id` 错误兼容，成功重试会清除旧错误。尚未实现的 v2 能力不会自动降级为模拟成功。
- 半径、地点 ID、真实分类目录、活动批次和登录仍等待服务端联调，详见第一轮接口依赖表。

底图实现依据 [OSM 瓦片编号与投影说明](https://wiki.openstreetmap.org/wiki/Slippy_map_tilenames)；访问方式遵循 [OSM 瓦片使用策略](https://operations.osmfoundation.org/policies/tiles/)。公共瓦片仅用于当前小规模开发演示，正式演示应提前确认网络可达和选用来源。

## 验证

复用原有 10 项 API 测试与 22 项浏览器检查，新增第二轮浏览器回归：

```powershell
node --check frontend/app.js
python -m unittest discover -s tests -p 'test_*.py' -v
node tests/browser-smoke.mjs
node tests/browser-round2.mjs
```

浏览器脚本仍需本地默认样例服务及开启 9224 调试端口的测试专用 Chrome，启动步骤见第一轮。第二轮测试会修改测试标签页的查询记忆，并拦截该标签页的部分请求注入故障；退出时恢复网络拦截和缓存设置，不修改运行数据库。

新增验证覆盖：刷新恢复分页、无效草稿不覆盖成功查询、损坏存储恢复、底图加载与归属、投影往返、底图缩放不提交查询、瓦片失败后保留结果、错误编号、非 JSON 响应、12 秒超时和成功重试清除错误。

真实底图已通过浏览器联网加载并保存为 `data/ui-verification/map-city-real.png`。确定性加载与故障测试使用拦截的测试瓦片，实际供应商可达状态单独记录在 `data/ui-verification/round2-result.json`，不将测试瓦片冒充真实地图截图。
