## 可用于报告的技术说明

### 数据模型和清洗语义

原始五列为 user_id、checkin_time、latitude、longitude、location_id。账号用户与签到数据中的 user_id 是两种实体，不能混用。ID 作为文本保留；存储时间为整秒 UTC；查询时间区间左闭右开；GeoJSON 坐标顺序为经度、纬度。地图采用真实 OSM 城市瓦片，WGS 84 数据经 Web Mercator 显示，不对 OSM 进行 GCJ-02 偏移。

清洗不是纯页面展示，导入任务实际调用 `cleaning.clean.clean()`，`backend/ingestion.py` 仅处理格式和字段映射，`cleaning_adapter.py` 保存有限质量样本。顺序与默认参数以团队代码及报告 config 为准；速度阈值是筛选规则，不能视为真实错误标签。已知地点坐标众数两缺陷与 coord_repair 计数偏差应列在讨论里，不写成全栈已经修正。

对账式可以用自然语言和表格；若写公式，应按课程要求使用 MathType 并解释变量。对账证明计数一致，不能证明所有坐标或被剔除记录语义正确。“清洗留存率”不是“准确率”。

### 双节点分片与版本服务

当前分片函数为 `sha256(user_id.encode('utf-8')).digest()[0] % 2`，不是 Python 内置 hash，也不是对完整哈希整数取模。单用户只查询所属节点；无用户限定时聚合两个节点。两节点各有只读 HTTP 服务和独立 SQLite 快照目录。原样入库器生成快照，全栈不添加私有索引。

控制库保存账号、任务、批次、目录和活动指针；签到事实位于两个节点。新任务构建新批次，核验完整性、分片和节点可读性后条件切换活动版本；历史版保留并支持有审计的回退。查询、导出与分享固定批次，避免翻页途中版本改变导致不一致。双节点在同一物理机上的实现达到课程允许虚拟节点的条件，但没有副本容灾、跨机自动分发或生产高可用部署。

### 空间查询与地图

矩形四边界包含端点；半径查询先保守边界预筛，再用 Haversine 球面距离精筛，支持极点和日期变更线附近的保守处理。宽矩形查询采用已有时间索引的有限前缀快路径，仅匹配足够时返回，否则执行完整筛选并受时间预算限制；不能描述为随机抽样。

地图点与表格为同一页，聚合只作用于当前页。待提交范围用虚线、成功条件用实线；地图瓦片与选区共用投影视野并同步更新，避免缩放漂移。有限签到连线按单用户、UTC 日期及最大六小时间隔分段，只表示记录顺序，不恢复真实路线或道路路径。

### 完整导出

网页创建后台任务；每个节点用主键游标分块枚举最多 20000 条候选并执行同样过滤，将结果逐块写到磁盘。全部成功后原子发布下载文件，取消/失败不提供半成品。CSV 对公式样式 ID 增加安全前缀，GeoJSON 保真；文件按节点与 ID 排列。任务只允许所属账号访问，有全局互斥和 Windows 元数据写入保护。不能将旧同步接口 10000 条限制误写成新网页功能仍被截断，也不能将没有记录数截断表述为无限磁盘或任意数据规模性能保证。

## 课程排版与提交检查

以下归纳自课程 PDF 第 2–5 页，最终以原文为准：

- 报告必须含技术设计、实施和结果，正文不少于 3000 字；提交完整代码供核验。
- 题目居中、黑体小四、1.5 倍行距；组员名单含学号姓名，组长第一，居中宋体五号、1.5 倍行距。姓名与贡献由本人确认。
- 子标题中文黑体小四、数字英文 Times New Roman，单倍行距、段前段后各半行；正文宋体五号、16 磅行距、首行缩进两字符。
- 图在正文先引用后出现，用绘图软件准备，不能用 Word 文本框等随意拼凑；必要的大图附件 JPG/TIF 不低于 600 dpi。图中文字按最终 Word 中的宋体六号大小核对。
- 表格采用三线表，首行表头完整、不用斜线表头，单位、空缺值和区间开闭准确；按附录示例准备中英文图题和表题。
- 公式用 MathType、10.5 磅，全篇顺序编号，参数首次定义，变量与正斜体按规范；不为凑字数增加与实现无关的公式。
- 参考文献按正文出现顺序编码，文中方括号引用；姓名、作者数量截断和中英文对照遵循附录。参考文献必须实际查阅，不复制附录中与本项目无关的样例，不虚构 DOI 或论文。
- PPT 不超过 5 分钟，应含案例、设计、技术、结果和总结。原文截止为 2026-12-02 17:00，汇报暂定 2026-12-03 18:00；组长另行确认后续通知。素材齐全不等于已经正式提交。
