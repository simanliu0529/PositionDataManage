## 核心实现

### 输入与清洗

`backend/ingestion.py` 是输入适配层。TXT / TSV 保持既有无头五列约定；CSV 使用表头；JSON 接受平面对象数组或单对象；JSONL / NDJSON 接受逐行对象。CSV / JSON 可自动识别常见别名或显式映射五字段。复杂嵌套结构、GeoJSON FeatureCollection 和自动坐标系识别不属于当前输入契约。

预览仅上传前 64 KiB，最多展示 5 条记录；完整文件仍重新解析和清洗。JSON 数组通过有界增量解码，拒绝重复键、截断与多余内容；JSONL / CSV 检查字节上限。非法记录保留计数及最多 5 条解析失败原内容，避免悄悄跳过。UTF-8、结构或字段映射严重错误导致整批失败，不替换活动数据。

映射和格式配置保存在控制库 `import_config`，摘要纳入规则版本，保证不同映射不会误复用同一任务。原上传文件和 SHA-256 保留，标准化中间文件只存在独立暂存目录。此前 `gowalla-clean-coordfix-db-1e1c602-v2:<配置摘要>` 属已撤回本地清洗修改的历史版本；当前使用 `gowalla-upstream-238168f-db-1e1c602-web-v3:<配置摘要>` 避免误复用。已有批次不自动重建。

`cleaning/clean.py` 和所有上游已有 `db/` 文件不属于全栈修改范围，保持 `753ec0f` 原文。此前首条坐标计数、修复目标和校正计数的修改已经撤回，不在全栈清洗适配器中重新实现。去重、UTC、异常坐标、零点、同刻冲突、隐含速度和舍入继续原样调用团队清洗器；分片和入库继续原样调用数据库模块。上游报告 `coord_repair` 不能直接标成“真实变化条数”或“准确修复条数”。

`backend/cleaning_adapter.py` 保存前 20 条字段有效记录及每种字段异常最多 5 条的真实前后证据。没有匹配输出的有效样本标为“未保留”，不臆造速度 / 冲突原因；精确计数查看规则汇总。CSV 序号不含表头，JSON 为数据记录序号，TSV 为物理行号，页面明确计数口径。这不是完整逐行血缘系统。

### 数据服务、组织和存储

`backend/data_services.py` 注册概览与导出，沿用主应用会话鉴权。概览取整批目录、导入报告和实时节点计数，显示用户、地点、月份、时间范围、留存及清单核验。普通用户不获得管理员任务摘要。留存率 = 最终入库 / 原始记录，不代表数据准确率；旧指标无法推断时返回 null。

导出独立调用全栈自有 `backend/batch_node.py` 的两个只读节点内部 `/export`，沿用同一 `where_clause`。每节点最多读 10001 条，在生成下载前核对总数；全部匹配超过 10000 返回 `422 EXPORT_LIMIT_EXCEEDED`，不会生成截断文件。任何必要节点失败均不产生部分成功文件。单用户查询与导出只访问其分片。节点模块迁移不修改团队的 `db/node.py`。

导出与交互分页分离。前端保存最近成功查询的条件及批次，表单未提交改动不影响导出。CSV 使用 UTF-8 BOM，带 batch_id / node / id；用户或地点 ID 具有电子表格公式前缀时加单引号保护。需要 ID 字符串完全保真时使用 GeoJSON。CSV 响应 `X-Export-Metadata` 为百分号编码的 JSON，GeoJSON 在正文 metadata 中携带批次、条件、数量、坐标系和范围。CSV 下载文件自身也有批次列。

持久化继续使用控制库与不可变双节点快照。新字段迁移以事务串行化，不重建旧库。发布后如最终报告保存异常，会保留成功发布的活动或历史快照并记录 `post_publish_warning`；清理仅针对未发布暂存数据。正式任务失败的残留分类计数也已清理。

### 界面与 GIS

保留原生前端和现有布局，新增真实概览，压缩重复入口卡片为快捷操作。导入页展示格式、映射、阶段、耗时、对账与样本，任务列表分页，临时轮询错误指数重试；退出后通过会话代数阻止迟到响应重填管理内容。

地图默认按需加载真实 OSM 城市瓦片，保留归属和浏览器缓存，失败明确提示并允许重试；失败不改变点位或假称底图成功。查询和导出为 WGS 84；底图仅作 Web Mercator 显示，不写入 GCJ-02 偏移。极区超过投影范围时明确切换坐标视图。

聚合只针对当前页，按屏幕距离合并并标数量；聚合可展开成员，完全同坐标的签到不无限放大。选中表行会将对应点从聚合中独立显示。窄屏点半径与数字按显示尺寸换算，窗口变化后重新绘制。矩形、半径、当前视野查询和点表联动继续走真实 API。

技术约定参考 [OSM 瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)；GeoJSON 使用 WGS 84 和经度在前的坐标顺序，参考 [RFC 7946](https://www.rfc-editor.org/rfc/rfc7946)。聚合交互借鉴按显示距离归组和点击展开的通用 GIS 模式，参考 [OpenLayers 官方示例](https://openlayers.org/en/latest/examples/cluster.html)，本项目未增加 OpenLayers 依赖。

## 宽矩形查询超时修复（同日后续）

用户在签到地图报告 `r_2a334cb70e4e4f2c`，提示“数据节点不可用或目标批次未就绪”。旧日志没有为普通 APIError 记录请求编号，不能直接按该编号检索；按相应时段的唯一签到查询 503 定位到矩形：西 -30.337780761718733、东 75.12214355468751、南 12.215867504405598、北 60.06459300257003。22:38:01 聚合 API 已返回 503，节点到 22:38:27 才尝试返回 200，因调用方已断开又出现连接中止堆栈。

两个节点的 `/count` 均可用，活动批次和快照完整。只读 EXPLAIN 显示宽框使用 `idx_latitude` 读取大量候选，再 `USE TEMP B-TREE FOR ORDER BY`；`LIMIT 51` 不能提前结束候选读取。全栈客户端的 8 秒超时与连接失败原来统一包装成同一 503，所以这次是慢查询被误报为节点或批次故障。

### 最小修改与准确性边界

- `backend/batch_node.py`：对无用户 / 地点限定、纬度跨度至少 10 度的矩形，先读取已有时间索引中的有限有序前缀，时间条件在前缀之前生效，再执行完整空间条件。只有已找到本节点所需的 `offset + limit + 1` 条匹配时才返回；不足则执行完整原筛选，不返回不完整的抽样结果。导出的 10001 条哨兵限制保持。
- 快路径只改变只读 SQL 的执行方式；没有新增或修改索引、业务表、快照内容、清洗、入库或分片规则。完整只读扫描作为独立对照，两个节点的前 51 条均与快路径逐条一致。
- SQL 设置整次查询 6 秒预算，前缀和回退共用；中断后清除 progress handler。HTTP 节点请求仍为 8 秒，浏览器仍为 12 秒，避免仅调大一个超时掩盖查询成本。无法在预算内完成时明确返回 504 `QUERY_TIMEOUT`，建议缩小时间或空间范围。
- `backend/worker.py` 的节点客户端区分传输超时、SQL 超时、失联、缺失批次与坏响应；不返回某一个成功节点的部分数据。服务日志补请求编号与错误分类，用户响应不包含 SQL 或本机路径。
- `backend/http_io.py`：客户端断开后停止发送，避免再写第二个 503 而产生重复堆栈。前端按超时错误显示“查询超时”，保留缩小条件建议，不再一律追加“检查服务”。

推荐在既有答辩流程中增加：用户 0、UTC 开始 `2010-10-17T00:00:00Z`、结束 `2010-10-20T00:00:00Z` 查询，检查 4 条记录 → 定位结果 → 加载签到连线 → 分享固定批次；管理员再比较历史及当前规则版本。无需为展示重新发布真实全量数据。

未测峰值内存、P95 或容器运行，不作相关性能承诺。上游众数与校正计数的 3 项预期失败仍交清洗负责人；全栈没有绕过原规则修正结果。真实轨迹还原、全批热力、RTree 等仍属未完成事项。

## 后台完整文件导出（2026-11-23）

用户需要导出筛选条件下超过 10000 条的全部记录。原 422 `EXPORT_LIMIT_EXCEEDED` 是旧同步接口的明确保护限制，未生成截断文件；不属于节点失联。网页现改用独立后台文件任务，不通过调大同步内存数组或分页 offset 绕过上限。

### 实现与使用

1. 在地图成功查询后点“完整导出 CSV”或“完整导出 GeoJSON”，固定最近成功条件及批次；后续修改表单不会改变任务。
2. 页面显示已处理候选记录与已写出数量；未知匹配总量时不伪造百分比。可取消，刷新本标签页会恢复当前账号最近任务状态。
3. 全部节点成功后才显示下载链接。浏览器直接下载磁盘文件，不先将全文件装入网页 Blob；CSV 安全前缀和 GeoJSON 原始 ID 语义保持。

`backend/export_jobs.py` 保存独立文件任务元数据，使用全局文件锁和进程内创建互斥限制同时一个任务；任务所有权、登录和 CSRF 沿用现有安全机制。`backend/batch_node.py` 新增只读 `/export-chunk`，以记录主键游标每次扫描最多 20000 条；没有 OFFSET 递增、全结果排序或抽样。单用户及地点条件利用现有索引枚举候选 ID，之后仍执行全部原空间与时间条件，窗口无匹配也继续推进。

CSV 与 GeoJSON 逐块写入 `data/exports/{任务编号}.part`，全部完成后原子改名并开放下载。按节点、记录 ID 升序输出，与交互地图的时间倒序不同；重复时间不依赖不稳定排序。失败和取消删除半成品，节点少一个也不发布部分文件。完成文件超过 24 小时在创建下一任务时清理；磁盘空间不足会失败。服务重启后未完成任务明确提示重建，不自动声称恢复断点。

新增 API：`POST /api/v2/exports`、`GET /api/v2/exports/{id}`、`POST /api/v2/exports/{id}/cancel`、`GET /api/v2/exports/{id}/download`。任务仅所属账号可查看、取消和下载。旧同步导出接口与有限签到连线仍保留 10000 条边界；其他同学的模块、表结构和索引没有变更。
